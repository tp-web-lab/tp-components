## Usage

### Initial content

::: tp-tabs
`tag` attribute
: ```html
  <tp-component-viewer tag="tp-button"></tp-component-viewer>
  ```

internal script
: ```html
  <tp-component-viewer>
    <script type="tp/html">
      <tp-button variant="brand" outlined>Try the attributes</tp-button>
    </script>
  </tp-component-viewer>
  ```

external file
: ```html
  <tp-component-viewer src="/docs/components/component-viewer/examples/button.html"></tp-component-viewer>
  ```
:::

### Documentation and preview

Choose Doc, Demo or API; switching panels preserves the demo configuration. Doc groups User interactions, Attributes, Methods, Events and CSS Properties. Events lists only custom events emitted by the component itself. API loads the generated TypeDoc page on first selection.

With `tag`, the viewer uses the component's introductory example. Script and file modes preserve the supplied content and attributes, and infer the first `tp-*` tag. Set `tag` explicitly to select a different component within a composed example. Relative resources resolve from the example file or author document; `api-src` selects another API manifest.

Demo controls are ordered as booleans, enumerated choices, then text, numeric, date and time fields on a wrapping row. Inherited settings belong to the documentation of their declaring component.

### Reading the demo source

In Demo, use the `</>` button beneath the preview to show HTML, tp-asciidoc, tp-latex, tp-markdown and tp-restructuredtext in tabs with readonly code editors. The source preserves the supplied content and reflects the current public attributes, without the internal DOM generated by the component.

### Metadata and interactions

`resetDefaults()` restores the documented attribute defaults and restarts the preview.

The control catalog is generated from existing attribute metadata, enum definitions and reviewed file fixtures with `pnpm viewer:sync-controls`. The build and example synchronization refresh it automatically.

The User interactions tab displays the complete Mouse interactions and Keyboard interactions documentation, including button descriptions and contextual-help shortcuts.

Command metadata comes from the `Shortcut` column in the Mouse interactions table in `interactions.md`. Use an explicit shortcut for a command with a key binding, `—` for a command without one, and an empty cell for an ordinary gesture or indicator. Keep toolbar buttons and palette commands distinct. A component without specific commands, such as `tp-button`, has no command rows.

### Documentation and live example

Doc describes the component's general API and documented controls, independently of the example's current state. Optional commands remain documented even when the example does not display them. Demo uses the supplied example and reflects changes made to its attributes and content. Its preview height follows the rendered content, including asynchronous updates and changes in width.

### Importing

::: tp-tabs
script
: Autoloading:

  ```html
  <script type="module" src="tp-loader.js"></script>
  ```

  Cherry picking:

  ```html
  <script type="module" src="/path/to/components/component-viewer/component-viewer.js"></script>
  ```

import
: ```js
  import "/path/to/components/component-viewer/component-viewer.js";
  ```

bundler
: ```js
  import "@tp/tp-components/components/component-viewer/component-viewer.js";
  ```
:::
