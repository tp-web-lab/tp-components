# Playground question

`TpPlaygroundQuestion<TPlayground extends TpPlayground<TpProject>>` is the abstract base for programming questions. It inherits `TpQuestion` through the shared `TpEditorQuestion` lifecycle and takes the response control's TypeScript type as its generic parameter. It does not register a `<tp-playground-question>` element: use a concrete language-specific tag. [Markup viewer questions](../markup-viewer-question/index.md) share that lifecycle but test rendered HTML instead of executing a programming project.

| Language | Compact interface | Full project interface |
| --- | --- | --- |
| JavaScript | [tp-javascript-viewer-question](../javascript-viewer-question/index.md) | [tp-javascript-playground-question](../javascript-playground-question/index.md) |
| TypeScript | [tp-typescript-viewer-question](../typescript-viewer-question/index.md) | [tp-typescript-playground-question](../typescript-playground-question/index.md) |
| Python | [tp-python-viewer-question](../python-viewer-question/index.md) | [tp-python-playground-question](../python-playground-question/index.md) |
| Prolog | [tp-prolog-viewer-question](../prolog-viewer-question/index.md) | [tp-prolog-playground-question](../prolog-playground-question/index.md) |

SQL is not included because its playground does not yet provide a test engine.

## Shared contract

| Attribute | Default | Role |
| --- | --- | --- |
| `src` | <code>""</code> | Initial source file or JSON project passed to the response control. It is not a question-definition JSON file. |
| `test` | <code>""</code> | External test file loaded on each submission. Submission requires this attribute. |
| `open` (from TpQuestion) | <code>false</code> | Expand the question initially; absent means collapsed. |

Language and interface are determined by the concrete class, not by attributes. Title, Prompt and Solution keep the normal definition-list format. Form is generated by the factory, and Feedback displays the external test run. Tests run on a temporary copy of the current code; reset and disconnection cancel stale results and release generated resources.

## TypeScript specialization

```ts
export class TpJavascriptViewerQuestion extends TpPlaygroundQuestion<TpJavascriptViewer> {
  protected override createPlayground(): TpJavascriptViewer {
    return new TpJavascriptViewer();
  }
}
```

Import `TpPlaygroundQuestion` from `components/playground-question/playground-question.js` and the chosen control from its own module. The base has no registry of languages and imports no concrete viewer or playground. The factory must return a new instance of the declared control type. A future specialization needs a `TpPlayground` implementation with a test-document builder.

## Migration

`<tp-programming-question language="python" mode="viewer" ...>` becomes `<tp-python-viewer-question ...>`. Keep `src`, `test`, `open` and the definition-list content. Replace `mode="playground"` with the corresponding `tp-LANG-playground-question` tag. `TpProgrammingQuestion` and its old custom element are removed rather than retained as aliases.
